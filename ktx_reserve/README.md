# KTX 빈자리 자동 예매

Python 3.11 이상에서 실행하는 터미널 프로그램입니다. 출발역·도착역·날짜·시간대·인원을 지정하면 조회 결과에서 원하는 열차와 좌석을 찾아 예약합니다. 기본 결제 방식은 코레일톡 앱에서 직접 결제하는 것입니다.

## 설치와 실행

맥·Linux 터미널에서 이 폴더로 이동해 실행하세요. Python 3.11 이상과 Git이 필요합니다.

```bash
bash setup.sh
```

Python 버전 오류가 나면 https://www.python.org/downloads/macos/ 에서 Python 3.13 이상을
설치하고 터미널을 다시 여세요. 설치 스크립트는 공식 설치본과 Apple Silicon·Intel Homebrew
경로를 찾아 사용하므로 맥의 기본 Python을 바꿀 필요가 없습니다.

삭제된 PyPI 배포 대신 공개 보존 포크의 커밋
`030576a6b41d874f35ebdf6b2d68ed76e70a1af7`을 설치합니다. 의존성 설치와 자동 테스트까지 실행하며,
시스템 Python을 변경하지 않습니다. 출처와 라이선스는 [THIRD_PARTY.md](THIRD_PARTY.md)를 참고하세요.

먼저 계정 없이 실제 서버의 역 정보와 열차 조회를 한 번 검사하세요:

```bash
bash run.sh --check --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:00 --to 15:00 --adult 2
```

`--check`는 로그인·예약·결제를 하지 않습니다. 첫 페이지의 열차를 좌석 유무와 무관하게 출력합니다.
날짜가 지났다면 미래 날짜로 변경하세요. 종료 코드 0은 조회 단계 성공, 1은 서버·네트워크 오류,
2는 옵션·설치 오류입니다. 이 검사가 성공해도 로그인과 예약 성공을 의미하지 않습니다.

로그인 후 조건에 맞는 좌석을 찾되 예약하지 않는 실행:

```bash
bash run.sh --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:00 --to 15:00 --adult 2 --dry-run
```

실제 예약:

```bash
bash run.sh --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:00 --to 15:00 --adult 2 --adjacent
```

실행 시 아이디·비밀번호를 터미널에 입력합니다. 비밀번호는 화면에 표시하지 않습니다.
`KORAIL_ID`, `KORAIL_PASSWORD` 환경변수도 지원합니다. 채팅이나 저장소에 인증정보를 적지 마세요.
클라우드의 프록시 치환용 비밀값은 비밀번호 암호화 전 원문을 제공하지 못하므로 그대로 사용할 수 없습니다.
실제 인증은 대화형 터미널 또는 실행 프로세스에 직접 주입되는 보안 환경변수가 필요합니다.

`Ctrl+C`로 중단합니다. 성공 후 코레일톡에서 예약·좌석·결제기한을 확인하고 결제하세요.
`--pay`는 카드 정보를 대화형으로 입력받아 결제하지만 실서버 결제는 아직 검증되지 않았습니다.
결제 결과가 불명확하면 추가 예약을 시도하지 않으므로 앱에서 먼저 확인하세요.

## 검증 상태 (2026-11-04)

- 고정 포크 설치, 실제 SDK 로딩, 의존성 검사 통과.
- 40개 테스트 통과. 실제 SDK의 HTTP 전송 직전까지 호출하고 응답 해석을 검사하는 테스트를 포함합니다.
  테스트 HTTP 응답은 고정된 모의 데이터이며 실서버 결과가 아닙니다.
- 2026-11-04 13:00 KST, 클라우드에서 실제 `--check` 실행 성공(종료 코드 0).
  역 정보 조회와 2026-11-06 서울→동대구 13시 이후 열차 10편 조회를 확인했습니다.
  예: KTX 105번 13:13, 37번 13:18, 217번 13:38. 로그인·예약·결제 요청은 하지 않았습니다.
- `smart.letskorail.com` 도메인 설정을 저장한 뒤 이전 CONNECT 403 차단이 해소됐습니다.
  게시 UI에는 실패가 표시됐지만 현재 실행 환경의 실제 조회는 성공했습니다.
  환경 게시·새 작업 복원은 아직 확인되지 않았습니다.
- 보존본의 `AppVersion=7.0.10`, `Version=250722001`, DynaPath SDK 2.0.1을 그대로 사용했습니다.
  이 조합의 열차 조회는 성공했으며, 인수인계에 적힌 버전 숫자로 임의 변경하지 않았습니다.
- **계정 로그인·실제 예약·결제는 미검증입니다.** 다음 단계는 본인 계정으로 `--dry-run`을 실행해
  로그인과 좌석 조건을 확인하는 것입니다. 조회 성공만으로 예매 전체 검증을 완료했다고 보지 않습니다.

재검증:

```bash
.venv/bin/python -B -m unittest discover -s tests -v
```

## 자동 결제 (개인카드)

맥에서도 기존 예약 명령 끝에 `--pay`를 붙이면 예약 성공 후 결제를 한 번 시도합니다.
시작할 때 개인카드 번호, 유효기간 YYMM, 카드 비밀번호 앞 2자리, 소유자 생년월일 YYMMDD를
터미널에서 입력합니다. 모두 화면에 표시하지 않으며 파일·명령줄 인자에 저장하지 않습니다.
카드번호 등은 채팅에 보내지 마세요. `--dry-run`과 함께 쓰면 카드 정보를 묻거나 결제하지 않습니다.
실제 카드 청구·발권은 아직 검증하지 않았습니다. 법인카드 입력 UI는 지원하지 않습니다.

```bash
caffeinate -i bash run.sh --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:49 --to 13:58 --adult 2 --seat general-only --pay
```

결제 성공 응답을 받으면 결과 알림을 표시하고 종료합니다. 설정한 디스코드에도 최종 결과를 보냅니다.
결제 응답을 받지 못하거나 오류가 나면 다시 예약·결제하지 않고 앱에서 확인하도록 안내합니다.
이 경우 실제 카드 승인이 됐을 가능성도 있으므로 코레일톡 승차권·예약 내역을 먼저 확인하세요.

## 실행 환경

기기 프로파일과 Android ID는 `~/.ktx_reserve/device.json`에 권한 0600으로 함께 저장해 재사용합니다.
이전 프로파일 파일도 읽을 수 있습니다. 저장 실패나 손상된 파일은 조용히 새 기기로 바꾸지 않고 중단합니다.
클라우드에서는 쓰기 가능한 폴더를 지정하세요:

```bash
bash run.sh --check --state-dir /workspace/ktx-state --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:00 --to 15:00
```

`KTX_STATE_DIR`로도 같은 폴더를 지정할 수 있습니다. 비밀번호·카드 정보는 파일에 저장하지 않습니다.
프록시 환경변수는 유지하며, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, `SSL_CERT_FILE` 순서로 설정된
인증서 번들을 사용합니다. TLS 검증을 끄지 않으며 각 요청의 제한시간은 30초입니다.

## Windows에서 실행

Windows용 Python 3.11 이상(3.13 권장)과 Git for Windows를 설치하세요.
Python 설치 화면에서 `Add python.exe to PATH`를 선택하고 터미널을 다시 여세요.
ZIP을 압축 해제한 폴더에서 PowerShell을 열고 다음을 실행합니다.

```powershell
.\setup.bat
.\run.bat --check --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:49 --to 13:58 --adult 2
```

명령 프롬프트(cmd)에서는 앞의 `.\` 없이 `setup.bat`, `run.bat`으로 실행해도 됩니다.
설치 후 실제 예약 명령 예시:

```powershell
.\run.bat --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:49 --to 13:58 --adult 2 --seat general-only --interval-min 1 --interval-max 2
```

회원번호와 비밀번호는 터미널에서 입력합니다. 자동 결제는 하지 않습니다.
실행 중에는 PC와 터미널을 켜두고 Windows 전원 설정의 절전 시간을 조절하세요.
`caffeinate`는 맥 전용이므로 윈도우 명령에는 넣지 않습니다. 중단은 Ctrl+C입니다.
기본 저장 폴더는 사용자 홈의 `.ktx_reserve`이며, Windows의 실제 접근 권한은 계정·폴더 ACL을 따릅니다.
Python 연동 테스트는 Linux에서 통과했습니다. Windows 런타임 및 휴대폰 알림은 사용자 PC에서 추가 확인이 필요합니다.

## 디스코드 휴대폰 알림

본인 Discord 서버의 텍스트 채널에서 채널 편집(톱니바퀴) → 연동(Integrations) →
웹훅(Webhooks) → 새 웹훅을 만들어 URL을 복사하세요. 서버·채널 관리 권한이 필요합니다.
권한이 없다면 본인 전용 서버와 채널을 만들면 됩니다. URL은 해당 채널에 메시지를 보낼 수 있는 비밀값입니다.
채팅·저장소에 올리지 말고 아래 설정 명령의 터미널 입력란에만 붙여넣으세요.

Windows PowerShell:

```powershell
.\discord.bat --setup
.\discord.bat --test
```

맥·Linux:

```bash
.venv/bin/python discord_notify.py --setup
.venv/bin/python discord_notify.py --test
```

`--setup` 입력은 화면에 표시되지 않습니다. 기본 `~/.ktx_reserve/discord.json`에 저장합니다.
예약 명령에 `--state-dir`을 사용했다면 설정·시험 명령에도 같은 폴더를 지정하세요.
프로세스에 직접 주입한 `DISCORD_WEBHOOK_URL`이 있으면 파일보다 우선합니다.
`--test`는 실제 채널에 시험 메시지를 보냅니다. 성공 여부뿐 아니라 휴대폰 수신까지 확인한 뒤 예약을 실행하세요.

휴대폰의 Discord 알림 권한과 해당 채널의 '모든 메시지' 알림을 켜세요.
PC에서 Discord를 사용 중이면 모바일 푸시가 지연될 수 있습니다. Discord의 모바일 푸시 비활성 시간 설정도 확인하세요.
프로그램은 예약 성공 시 날짜·구간·열차·인원·좌석·결제기한을 전송하며, 회원번호·예약번호·비밀번호·카드정보는 보내지 않습니다.
공유 채널 대신 본인 전용 채널을 권장합니다. 멘션은 자동으로 발생시키지 않습니다.
`--demo`와 `--dry-run`에서는 Discord 알림을 보내지 않습니다. 전송 실패해도 예약을 다시 시도하지 않습니다.
설정을 지우려면 예약 프로그램을 멈춘 뒤 `discord.json`을 삭제하고 환경변수를 사용했다면 함께 해제하세요.

## 개발용 데모

외부 연결 없이 로직만 보려면 `--demo`를 사용합니다. 실제 티켓이 생기지 않으며
역 이름·운행 데이터·서버 호환성은 검증하지 않습니다. `--dry-run`만 지정하면 실제 서버에 접속합니다.

```bash
bash run.sh --demo --dep 서울 --arr 동대구 --date 2026-11-06 --from 13:00 --to 15:00 --adult 2 --adjacent
```

## 옵션

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `--dep` / `--arr` | 출발역 / 도착역 | 필수 |
| `--date` | 출발일, 예: `2026-11-06` | 필수 |
| `--from` / `--to` | 출발 시간 범위, 예: `13:00` / `15:00` | 필수 |
| `--adult` / `--child` / `--senior` | 어른 / 어린이 / 경로 인원, 총 1~9명 | 1 / 0 / 0 |
| `--train` | `ktx`, `all`, `saemaeul`, `mugunghwa`, `itx-cheongchun` | `ktx` |
| `--seat` | `general-first`, `general-only`, `special-first`, `special-only` | `general-first` |
| `--adjacent` | 2명 이상일 때 인원수만큼 붙은 좌석인지 검사 | 끔 |
| `--trains` | 쉼표로 구분한 열차번호, 예: `105,107` | 전부 |
| `--interval-min` / `--interval-max` | 조회 간격 범위(초), 최소 0.5초 | 1.0 / 2.0 |
| `--check` | 로그인 없이 실제 역·열차 조회 1회 | 끔 |
| `--state-dir` | 기기 정보 저장 폴더 | `~/.ktx_reserve` |
| `--demo` | 외부 연결 없는 모의 실행 | 끔 |
| `--dry-run` | 좌석 발견 후 예약 전에 종료 | 끔 |
| `--pay` | 예약 후 카드 결제 시도, 실서버 미검증 | 끔 |

## 동작과 오류 처리

- 조회한 열차 중 시간대·번호·좌석 등급이 맞는 열차만 예약합니다. 기본 간격은 1~2초입니다.
- `--adjacent`는 같은 호차에서 같은 행의 연속 알파벳 또는 연속 숫자 좌석을 인정합니다. 실제 객차 배치도에 따른 물리적 인접 여부까지 보장하지 않습니다. 좌석 정보가 없거나 인원수와 맞지 않아도 취소합니다. 취소한 열차는 60초 동안 건너뜁니다.
- 예약대기는 취소합니다. 취소 실패나 예약 요청 결과가 불명확한 통신 오류는 중단하고 앱에서 확인하도록 안내합니다.
- 비밀번호 오류와 이용제한은 즉시 중단합니다. 로그인 일시 오류는 30·60·90·120초, 5회 연속부터 600초 간격으로 재시도하며 시간대가 지나면 종료합니다.
- 세션 만료는 재로그인, `MACRO ERROR`는 60초 대기, 일반 통신 오류는 5초 대기합니다. 버전 거절 `-8204`는 중단합니다.
- 실제 실행의 기기 프로파일은 `~/.ktx_reserve/device.json`에 재사용합니다. 맥은 알림 센터, Linux는 터미널 벨을 사용합니다.

본인 탑승용으로 사용하고 코레일 이용 정책을 확인하세요. 반복 조회는 계정 이용제한을 초래할 수 있습니다. 실서버 동작을 확인하기 전에는 코레일톡의 예약대기 등 공식 기능을 이용할 수 있습니다.
